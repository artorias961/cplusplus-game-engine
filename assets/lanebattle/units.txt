# ---------------------------------------------------------------------------
# units.txt — Lane Battle's roster.
#
# Edit this and run the game; no compiler involved. The values here are the
# same ones compiled into LaneBattle.h as defaults, so deleting this file
# changes nothing and corrupting it changes only the fields it corrupts.
#
# Each [unit] either updates the row whose `name` matches or adds a new one.
# Any field left out keeps whatever it had, so a file that only wants archers
# cheaper can say exactly that and nothing else:
#
#     [unit]
#     name = ARCHER
#     cost = 80
#
# Each unit has its OWN cooldown, so a full purse cannot be poured into one
# type: spending it means sending something else. That is what makes the
# button bar a decision rather than a shop.
#
# Balance, in one paragraph: RUNNER is the best damage per gold and dies to
# anything. SOLDIER beats a runner one-to-one and loses to two. ARCHER
# outranges both and cannot survive being reached, so it is worth having only
# behind a front line. No single one of them wins on its own — there are tests
# that fail if that stops being true.
# ---------------------------------------------------------------------------

# creating a fourth upgrade that would do nothing.
#

# The campaign. Unlike units, these REPLACE the built-in list rather than
# merging into it: a campaign is an ordered sequence, so a file describing
# three stages means a three-stage campaign.
#
#   enemy_income         multiplier on the opponent's gold rate
#   enemy_castle_health  how much castle there is to chew through
#   wave_size            how many units it banks for before spending
#   composition          roster indices it cycles: 0 runner, 1 soldier, 2 archer
#
# The shape of this curve was measured, not chosen. Every stage is played by
# three different armies in the tests, and the numbers below are the third
# attempt: the first left three stages nobody could win, and the second put a
# wall at stage three because a LEAN composition beats a padded one even at
# lower income. Early stages are diluted with runners on purpose.
#
# Roughly: stage 1 teaches you the button, stage 2 that one unit type is not
# enough, stages 3-7 that composition wins, and stage 8 that composition alone
# does not — it needs two income upgrades behind it.
